# Spec: Build a giter8 (g8) template for service/domain/package renaming

## Overview
Turns the existing order-service reference implementation into a giter8 template, parameterized
by `domain_name` and `package_name`, so a new purerest-based microservice can be generated by
renaming rather than hand-editing. This is the first step toward this project's eventual
generator (product.md's "Components"); field-level parameterization and CI/CD pipeline wiring
are separate, later backlog items.

## Functional Requirements
1. New `src/main/g8/` directory (standard giter8-in-source-repo convention) containing a
   templated copy of the current reference service.
2. `default.properties` with sane defaults so an unparameterized `sbt new` still produces a
   buildable example.
3. **Two template properties:**
   - `domain_name` (lowercase, singular, e.g. `widget`) — drives sbt project/Docker image name,
     Postgres database & table name, REST resource path (naive `+s` pluralization), Scala class/
     identifier names (`Order`→`Widget`, etc.), and the `service-name` config default/tracer name.
   - `package_name` (e.g. `widgetservice`, or a reverse-domain style like
     `com.mycompany.widgetservice`) — the Scala package declaration/directory structure.
     Defaults to `$domain_name$service` in `default.properties` (referencing `domain_name`), but
     independently overridable at generation time.
4. Everything NOT domain-specific stays fixed: purerestlib version pin (0.1.0), library versions,
   Docker/sbt-native-packager config, the `ClientResilienceExampleSuite` pattern (mechanically
   repackaged, otherwise unchanged), health endpoints, the one-db-per-service convention itself.
5. Generated via `sbt new file://<path-to-this-repo>` (local file template, no separate
   published template repo).
6. README documents prerequisites, the exact command, both properties and their defaults, and
   the naive-pluralization caveat.

## Acceptance Criteria
- `sbt new file://<repo-path>` with `domain_name=widget` (default `package_name`) produces a
  compilable, fully-renamed standalone service.
- The generated service's `sbt scalafmtCheck test` passes, 0 failures.
- No leftover `order`/`Order`/`orderservice` references anywhere in the generated output
  (grep-verified).
- Overriding `package_name` independently (e.g. `com.example.widgetservice`) also generates and
  compiles correctly.
- This repo's own existing reference service (the template's source) is untouched and still
  builds/tests standalone.

## Out of Scope
- Parametrized field-codegen (next backlog item).
- Automated generation → repo-creation → push → CI pipeline (following backlog item).
- Correct pluralization for irregular English nouns — naive `+s` only, documented as a known
  limitation.
- Publishing the template to a separate/public giter8-discoverable repo.
- Renaming purerest's own `order-service`.
